# Набор тестовых задач для замера экономии токенов (раздел 14.1 ТЗ)

20 реальных задач для сравнительного замера с Atlas и без него на 3 проектах (малый, средний, большой).

## Категория 1: Навигация и поиск (5 задач)

1. **Найти определение функции** — найти, где объявлена функция `process_payment` в проекте
2. **Найти все вызовы** — найти все места, где вызывается функция `validate_user`
3. **Найти импорты модуля** — какие модули импортируют `auth_service`
4. **Найти класс по описанию** — найти класс, отвечающий за подключение к базе данных
5. **Найти константу** — найти значение константы `MAX_RETRY_COUNT`

## Категория 2: Анализ влияния изменений (5 задач)

6. **Оценить влияние изменения** — если изменить функцию `calculate_tax`, какие другие функции затронуты?
7. **Найти тесты для функции** — найти все тесты, которые проверяют функцию `parse_config`
8. **Найти вызовы API** — найти все места, где используется внешний API `stripe`
9. **Найти дублирование кода** — найти функции с похожей сигнатурой в разных модулях
10. **Найти мёртвый код** — найти функции, которые не вызываются ниоткуда

## Категория 3: Понимание структуры (5 задач)

11. **Объяснить структуру модуля** — как организован модуль `api/`, какие у него точки входа?
12. **Найти точки входа** — какие функции являются точками входа в приложение?
13. **Найти зависимости модуля** — от каких модулей зависит `auth/`?
14. **Найти циклические зависимости** — есть ли циклические импорты между модулями?
15. **Найти основные хабы** — какие файлы имеют наибольшее число входящих связей?

## Категория 4: Отладка и тестирование (5 задач)

16. **Найти причину падающего теста** — тест `test_login` падает, где может быть причина?
17. **Найти связанный тест** — какой тест проверяет функцию `process_order`?
18. **Найти ошибку разбора** — какие файлы имеют ошибки при парсинге?
19. **Найти изменения за период** — какие файлы менялись за последние 7 дней?
20. **Найти документацию** — найти README или ADR, описывающий архитектуру авторизации

## Методика выполнения (раздел 14.1)

Для каждой задачи фиксируются:
- Суммарные токены (вход + выход)
- Число вызовов инструментов
- Время выполнения
- Правильность результата (по заранее заданному критерию)

Каждая пара прогонов повторяется не менее 3 раз; сравниваются медианы.
Экономия не засчитывается, если доля правильных результатов с Atlas ниже, чем без него.
