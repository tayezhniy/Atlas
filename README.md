# Atlas — навигатор по проекту для нейросетей

Локальное десктопное приложение, которое индексирует проект, строит граф связей между его частями и отдаёт нейросети компактную карту вместо чтения файлов целиком.

## Структура репозитория

```
atlas/
  crates/
    atlas-core/        # модель данных, граф, ранжирование
    atlas-indexer/     # обход, парсинг, наблюдатель, инкрементальное обновление
    atlas-langs/       # запросы tree-sitter по языкам (плагины)
    atlas-store/       # SQLite, миграции, FTS
    atlas-mcp/         # MCP-сервер, инструменты, бюджеты, форматирование ответов
    atlas-cli/         # команды: index, mcp, run, doctor
  app/
    electron/         # оболочка Electron, IPC между UI и ядром Rust
    ui/                # интерфейс: граф, дерево, просмотр, панели
  docs/                # документация
  fixtures/            # эталонные проекты для тестов
  bench/               # сценарии замера токенов и производительности
```

## Стек

- Ядро: Rust
- Парсинг: tree-sitter
- Хранилище: SQLite + FTS5
- MCP: протокол JSON-RPC по stdio, реализован вручную без внешнего SDK
  (версия протокола по умолчанию `2024-11-05`, клиентская версия принимается в `initialize`)
- Оболочка: Electron 28
- Интерфейс: TypeScript + React, Sigma.js для графа, CodeMirror 6 для просмотра кода

## Этапы разработки

1. **Этап 0 — Прототип**: код готов, **гейт не пройден** — экономия токенов не замерена с реальной моделью (`bench/` только симулирует агента)
2. **Этап 1 — MVP**: 7 инструментов, ранжирование, бюджеты, наблюдатель (`atlas watch`), журнал вызовов
3. **Этап 2 — Интерфейс**: дерево, граф файлов, просмотр в 4 режимах, переход к определению, инспектор, палитра команд, отчёт. Настройки сохраняются, но пока не применяются
4. **Этап 3 — Отчёты и языки**: отчёт Markdown/JSON, парсеры tree-sitter для дополнительных языков
5. **Этап 4 — Релиз** (не начат): установщики, подпись, автообновление, MCP по HTTP

## Начало работы

### Ядро (Rust)

```bash
# Сборка ядра
cargo build --release

# Индексация проекта
cargo run --bin atlas-cli -- index /путь/к/проекту

# Запуск MCP-сервера
cargo run --bin atlas-cli -- mcp

# Тесты
cargo test
```

### Интерфейс (Electron + React)

Требуется Node.js и npm:

```bash
cargo build --release   # из корня: интерфейс запускает этот бинарник
cd app/ui
npm install
npm run build           # проверка типов и сборка
npm run electron        # запуск приложения
```

Разработка: `npm run dev` в одном терминале и `npm run electron:dev` в другом
(синтаксис переменной окружения рассчитан на Linux и macOS).
Другой бинарник можно указать переменной `ATLAS_BIN`. Данные для интерфейса идут
методом `atlas/ui` того же сервера `atlas-cli mcp`; нейросети этот метод не объявляется.

### CLI-команды

Бинарник называется `atlas-cli` (`cargo run --bin atlas-cli -- <команда>`).

| Команда | Описание |
|---|---|
| `index <путь>` | Индексировать проект; индекс лежит в `<проект>/.atlas/index.db` |
| `mcp [--project <путь>]` | MCP-сервер по stdio; если индекса нет, строит его сам |
| `doctor [--project <путь>]` | Проверка индекса: целостность, свежесть, число узлов и связей |
| `watch [--project <путь>]` | Наблюдать за файлами и переиндексировать изменённые по ходу дела |
| `settings get <ключ> [--project <путь>]` | Получить значение настройки проекта |
| `settings set <ключ> <значение> [--project <путь>]` | Установить значение настройки (JSON) |
| `settings all [--project <путь>]` | Получить все настройки проекта |
| `report [--project <путь>] [--format json|markdown]` | Экспорт отчёта проекта |
| `run <команда>` | Выполнить команду и отфильтровать вывод |

### Подключение к Claude и другим MCP-клиентам

```json
{
  "mcpServers": {
    "atlas": {
      "command": "/путь/к/atlas-cli",
      "args": ["mcp", "--project", "/путь/к/проекту"]
    }
  }
}
```

Бинарник после `cargo build --release`: `target/release/atlas-cli`.

Инструменты: `overview`, `search`, `outline`, `read` (режимы `signature`, `doc`, `folded`, `full`),
`neighbors`, `context_for`, `status`. Все только читают; пути вне проекта отклоняются.
Каждый вызов пишется в таблицу `call_log`.

### Известные ограничения

- Связи по вызовам статические: свой файл (`certain`) → импортируемые файлы (`likely`) → единственный кандидат в проекте (`likely`) → соседи по каталогу (`guess`) → до 3 кандидатов (`guess`). Динамические вызовы и рефлексия не определяются; у каждой связи есть метка уверенности.
- Маскирование секретов — эвристика по именам (`password`, `secret`, `…token`, `api_key` и т. п.) и префиксам ключей. Секрет под нейтральным именем, на следующей строке после ключа (JSON, блоки и списки YAML), в XML или в многострочной строке оно не распознает; такие файлы исключайте через `.atlasignore`.
- Статистика разрешения вызовов видна в выводе `atlas index`: `calls_linked`, `calls_unresolved`, `calls_guessed`.
- Если символ переименован или удалён, связи на него из неизменённых файлов исчезают до их переиндексации (связи на сохранившиеся символы переносятся).
- Наблюдатель файлов подключён: `atlas watch` переиндексирует изменённые файлы по событиям (`incremental.rs`, `watcher.rs`). Инкрементальный режим без наблюдателя — повторный `atlas index`: неизменённые файлы пропускаются по хешу.
- LSP экспериментален и выключен: включается переменной `ATLAS_LSP=1` и запускает найденные в PATH языковые серверы. Пользы для графа пока не подтверждено.
- HTTP-транспорт MCP — этап 4.
- Если база создана старой версией (до исправления схемы FTS), удалите `.atlas/` и проиндексируйте заново.
