# Atlas — навигатор по проекту для нейросетей

Локальное десктопное приложение, которое индексирует проект, строит граф связей между его частями и отдаёт нейросети компактную карту вместо чтения файлов целиком.

## Структура репозитория

```
atlas/
  crates/
    atlas-core/        # модель данных, граф, ранжирование
    atlas-indexer/     # обход, парсинг, наблюдатель, инкрементальное обновление
    atlas-langs/       # запросы tree-sitter по языкам (плагины)
    atlas-store/       # SQLite, миграции, FTS
    atlas-mcp/         # MCP-сервер, инструменты, бюджеты, форматирование ответов
    atlas-cli/         # команды: index, mcp, run, doctor
  app/
    electron/         # оболочка Electron, IPC между UI и ядром Rust
    ui/                # интерфейс: граф, дерево, просмотр, панели
  docs/                # документация
  fixtures/            # эталонные проекты для тестов
  bench/               # сценарии замера токенов и производительности
```

## Стек

- Ядро: Rust
- Парсинг: tree-sitter
- Хранилище: SQLite + FTS5
- MCP: протокол JSON-RPC по stdio, реализован вручную без внешнего SDK
  (версия протокола по умолчанию `2024-11-05`, клиентская версия принимается в `initialize`)
- Оболочка: Electron 28
- Интерфейс: TypeScript + React, Sigma.js для графа, CodeMirror 6 для просмотра кода

## Этапы разработки

1. **Этап 0 — Прототип** (текущий): обход проекта, символы, импорты и вызовы (Rust, Python, TypeScript), SQLite + FTS5, рабочий MCP-сервер по stdio с 7 инструментами, `atlas index` и `atlas doctor`, скрипты замера. Остаётся: сам замер экономии токенов (гейт этапа)
2. **Этап 1 — MVP**: все 7 инструментов, ранжирование, бюджеты, наблюдатель файлов, журнал вызовов
3. **Этап 2 — Интерфейс**: дерево, граф, просмотр, поиск, инспектор
4. **Этап 3 — Отчёты и бета**: экспорт отчёта, вторая волна языков
5. **Этап 4 — Релиз**: установщики, подпись, автообновление

## Начало работы

### Ядро (Rust)

```bash
# Сборка ядра
cargo build --release

# Индексация проекта
cargo run --bin atlas-cli -- index /путь/к/проекту

# Запуск MCP-сервера
cargo run --bin atlas-cli -- mcp

# Тесты
cargo test
```

### Интерфейс (Electron + React)

Требуется Node.js и npm:

```bash
cd app/ui
npm install
npm run dev      # Режим разработки (Vite + Electron)
npm run build    # Сборка UI для продакшена
```

После сборки UI приложение запускается через `npm run electron` (Electron оболочка),
которая порождает Rust-бинарник `atlas-cli mcp` и проксирует JSON-RPC через stdio.

### CLI-команды

Бинарник называется `atlas-cli` (`cargo run --bin atlas-cli -- <команда>`).

| Команда | Описание |
|---|---|
| `index <путь>` | Индексировать проект; индекс лежит в `<проект>/.atlas/index.db` |
| `mcp [--project <путь>]` | MCP-сервер по stdio; если индекса нет, строит его сам |
| `doctor [--project <путь>]` | Проверка индекса: целостность, свежесть, число узлов и связей |
| `watch [--project <путь>]` | Наблюдать за файлами и переиндексировать изменённые по ходу дела |
| `run <команда>` | Фильтр вывода команд — пока не реализован (этап 3) |

### Подключение к Claude и другим MCP-клиентам

```json
{
  "mcpServers": {
    "atlas": {
      "command": "/путь/к/target/release/atlas-cli",
      "args": ["mcp", "--project", "/путь/к/проекту"]
    }
  }
}
```

Инструменты: `overview`, `search`, `outline`, `read` (режимы `signature`, `doc`, `folded`, `full`),
`neighbors`, `context_for`, `status`. Все только читают; пути вне проекта отклоняются.
Каждый вызов пишется в таблицу `call_log`.

### Известные ограничения прототипа

- Связи по вызовам статические. Разрешение имени идёт по цепочке: свой файл (`certain`) → импортируемые файлы (`likely`) → единственный кандидат в проекте (`likely`) → соседи по каталогу или единственная функция/метод (`guess`) → до 3 кандидатов, связи `guess` на все. Динамические вызовы, рефлексия и общие имена (`new`, `get`…) по-прежнему определяются не полностью; в ответах MCP у каждой связи есть метка уверенности.
- Статистика разрешения вызовов видна в выводе `atlas index`: сколько вызовов найдено, сколько превратилось в связи и сколько не разрешено.
- Если символ переименован или удалён, связи на него из неизменённых файлов исчезают до их переиндексации (связи на сохранившиеся символы переносятся).
- Наблюдатель файлов подключён: `atlas watch` переиндексирует изменённые файлы по событиям (`incremental.rs`, `watcher.rs`). Инкрементальный режим без наблюдателя — повторный `atlas index`: неизменённые файлы пропускаются по хешу.
- HTTP-транспорт MCP, отчёт в Markdown, карта проекта и интерфейс (граф, Sigma.js) — этапы 2–3.
- Если база создана старой версией (до исправления схемы FTS), удалите `.atlas/` и проиндексируйте заново.
